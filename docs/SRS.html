1. المقدمة (Introduction)

1.1 الهدف من النظام (Purpose)

الهدف من نظام QuizCraft هو تمكين المعلمين والمؤسسات التعليمية من تحويل اختبارات الاختيار من متعدد (MCQ) المخزنة في ملفات PDF ذات هيكل منظم إلى اختبارات تفاعلية أونلاين فوراً، دون الاعتماد على نماذج الذكاء الاصطناعي الخارجية (No AI Dependencies)، بالاعتماد الكامل على خوارزمية قطعية ومحددة (Deterministic Text & Regex Parsing).

1.2 النطاق (Scope)

  • رفع ملف PDF بهيكل ثابت يحتوي على أسئلة وخيارات ومفاتيح حل.
  • استخراج الأسئلة والخيارات آلياً وعرضها على واجهة مراجعة سهلة للمعلم.
  • توليد كود دخول فريد لكل امتحان ومشاركته مع الطلاب.
  • منصة مخصصة للطلاب لحل الامتحان مع عداد تنازلي نشط وتسليم تلقائي عند نفاد الوقت.
  • تصحيح آلي مباشر واحتساب الدرجات ونسب النجاح والرسوب فور إرسال الإجابات.
  • لوحة تحكم للمدرس لتتبع حضور الطلاب وتحليل الأسئلة الأكثر صعوبة.

2. المعمارية المعتمدة (4-Layer Clean Architecture)

تم تصميم النظام وفق أحدث معايير هندسة البرمجيات النظيفة في منصة .NET عبر الفصل الصارم بين طبقات العمليات:

3. المتطلبات الوظيفية (Functional Requirements)

رقم المطلب اسم الميزة الوصف والتفاصيل
FR-01 استخراج الـ PDF بدون AI استخدام مكتبة UglyToad.PdfPig واستخراج الأسئلة بنمط Regex للمطابقة القطعية (مثل: 1. What is... وخيارات A) B) C) D)).
FR-02 مراجعة وتعديل الأسئلة إتاحة فحص الأسئلة المستخرجة وتعديل الإجابة النموذجية وتحديد درجات كل سؤال قبل نشر الامتحان.
FR-03 توليد كود الدخول (Access Code) توليد كود مميز عشوائي (مثل: QC-583921) للوصول للامتحان دون الحاجة لتسجيل حساب معقد للطلاب.
FR-04 واجهة حل الامتحان للطالب حجب الإجابة الصحيحة تماماً من نموذج الـ API لمنع الغش عبر أدوات المطورين (F12/DevTools).
FR-05 مؤقت الامتحان والتسليم التلقائي حساب الوقت المتبقي وتسليم الإجابات تلقائياً بمجرد وصول العداد التنازلي إلى الصفر.
FR-06 التصحيح التلقائي الفوري مقارنة إجابات الطالب بالإجابات النموذجية، احتساب المجموع، وإصدار النتيجة والنسبة المئوية فوراً.
FR-07 تتبع الحضور والنتائج (Tracker) عرض قائمة كاملة بالطلاب الذين قاموا بالحل، درجاتهم، وتحديد السؤال الأكثر خطأً (Hardest Question).

4. المتطلبات غير الوظيفية (Non-Functional Requirements)

المعيار المواصفات المستهدفة
السرعة والأداء (Performance) معالجة ملف PDF المكون من 50 سؤالاً في زمن يقل عن 1.5 ثانية بدون استهلاك سيرفرات خارجية.
الأمان والنزاهة (Security) فصل كائن TakeExamDto عن ExamDetailDto لضمان عدم إرسال حقل IsCorrect للطلاب نهائياً.
الاعتمادية (Reliability) الاعتماد على مكتبة مفتوحة المصدر نقية C# بدون مكتبات C++ خارجية أو خدمات سحابية مدفوعة.
قابلية الصيانة (Maintainability) فصل طبقات التطبيق الـ 4 بحيث يمكن استبدال قاعدة البيانات من SQLite إلى SQL Server أو PostgreSQL دون لمس طبقة الـ Core أو الـ API.

5. مخطط الكيانات وقاعدة البيانات (Entities & Data Model)

  • Exam: Id, Title, AccessCode, DurationMinutes, TotalMarks, PassPercentage, Status, CreatedAt.
  • Question: Id, ExamId, QuestionNumber, Text, Type, Points, Explanation.
  • Option: Id, QuestionId, Label (A/B/C/D), Text, IsCorrect.
  • Submission: Id, ExamId, StudentName, StudentIdentifier, Score, TotalMarks, IsPassed, AutoSubmittedDueToTimeout.
  • StudentAnswer: Id, SubmissionId, QuestionId, SelectedOptionId, EarnedPoints, IsCorrect.
